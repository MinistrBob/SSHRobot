# AGENTS.md — SSHRobot

## Назначение

Лёгкий инструмент для массового выполнения команд по SSH на множестве
серверов и для файловых операций (SFTP `get`/`put`). Создан для личного
применения в случаях, когда Ansible недоступен. **Не является заменой
Ansible** — функциональность и удобство у́же осознанно.

Платформа: Python 3.13, единственная runtime-зависимость — `paramiko`.

## КРИТИЧЕСКОЕ ПРАВИЛО: запуск только по явному разрешению пользователя

**НИКОГДА самостоятельно не запускать НИЧЕГО на реальных серверах/стендах.**
Это очень строгое правило:

- ЗАПРЕЩЕНО самому запускать `ssh_robot_executor.py`,
  `ssh_robot_file_worker.py`, `ssh_SL_generator.py` и любые другие
  скрипты/команды, выполняющие действия по SSH на хостах стендов
  (в т.ч. «проверочные», «безобидные», `c_pwd`/debug-модули).
- Разрешено агенту: читать/создавать/править файлы проекта (SETTINGS.py,
  SL.py, seq_comm_*.py и т.п.), локальные неблокирующие проверки
  (например `python -c "import ..."` для проверки синтаксиса).
- Любой запуск на стендах — ТОЛЬКО после явного разрешения пользователя
  в текущем диалоге. Подготовил конфиг → показал пользователю, ЧТО будет
  запущено и НА КАКИХ хостах → ждём разрешения. Предыдущие разрешения
  («запусти» в прошлой сессии/задаче) не действуют для новых запусков.
- Это инструмент массового выполнения команд: одна ошибка в модуле
  команды затрагивает десятки серверов стенда сразу.

## Структура проекта

### Точки входа (entry points)

| Файл                       | Назначение                                                                 |
|----------------------------|----------------------------------------------------------------------------|
| `ssh_robot_executor.py`    | Выполняет модуль команд (`SETTINGS.module`) по списку серверов (`SETTINGS.sl`). Главная логика — функция `main()`. |
| `ssh_robot_file_worker.py` | Выполняет файловые операции (SFTP) из `SETTINGS.fl` по списку серверов. Запускается как скрипт (нет `main()`). |
| `ssh_SL_generator.py`      | Генерирует текст словаря `server_list` по диапазону IP. Утилита, запуск отдельно. |

### Конфигурация (приватные, gitignored файлы)

Эти файлы **НЕ коммитятся** (см. `.gitignore` и `exclude.txt`) и переносятся
между машинами вручную:

| Файл             | Назначение                                                                 | Шаблон               |
|------------------|----------------------------------------------------------------------------|----------------------|
| `SETTINGS.py`    | Текущая конфигурация запуска: выбранный `sl`, `module`/`fl`, флаги показа, порт. | `SETTINGS_example.py` |
| `SL.py`          | Словарь серверов `server_list`: `{ip: {login, password, hostname, [port]}}`. | — |
| `FOL.py`         | Список файловых операций `file_operations_list`: `[('get'\|'put', src, dst), ...]`. | — |
| `CL_archive.txt` | Архив использованных команд (история).                                     | —                    |
| `seq_comm_*.py`  | Одноразовые/стендовые модули команд.                                       | —                    |

> **ВАЖНО:** `SETTINGS.py`, `SL.py`, `FOL.py` содержат пароли и приватные
> данные. Никогда не коммить их и не выводи пароли в логи/вывод агента.

### Модули команд (MOD)

Файл модуля (имя любое, напр. `CentOS8.py`) содержит набор словарей-команд.
Импортируется в `SETTINGS.py` как `import CentOS8 as MOD` (или любое имя).

Формат словаря-команды:

```python
example = {
    'check':           None,      # str | None — команда проверки
    'check_result':    None,      # dict | None — ожидаемый результат проверки
    'command':         None,      # str | None — основная команда (главные действия)
    'show':            None,      # str | None — команда для отображения (до/после)
    'execute_anyway':  False,     # bool — выполнять main даже если check не пройден
    'show_after':      True,      # bool — показывать show после выполнения
    'show_before':     True,      # bool — показывать show до выполнения
}
```

`check_result`:
```python
{'type': "int",          # "int" | "str"
 'value': 1,             # ожидаемое значение
 'execute': 4,           # оператор для решения "выполнять main": {1 == 2 != 3 < 4 > 5 <= 6 >=}
 'ok': 1,                # оператор для "не выполнять main" (уже в нужном состоянии)
 'error': 3}             # оператор для "ошибка"
```

Логика (`ssh_robot_executor.py`): `show before` → `check` → по результату
(`exec` / `noexec` / `error`) → `command` → `show after`.

Для `str`-типа сравнение только по `==` (value == result → `noexec`, иначе `exec`).

## Окружение / запуск

```bash
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# Перед запуском создать приватные файлы:
cp SETTINGS_example.py SETTINGS.py   # и отредактировать
# создать SL.py со словарём server_list

python3 ssh_robot_executor.py
python3 ssh_robot_file_worker.py
```

Python: 3.13 (минимум 3.12). Виртуальное окружение `.venv` обязательно
(не коммитится).

## Архитектура / поведение

- **`ssh_robot_executor.py`** — функция `main()` проходит по
  `SETTINGS.sl.items()` и для каждого сервера вызывает `one_server()`.
  Сбор результатов идёт в `final_result` со списками: `list_success`,
  `list_error_connect`, `list_error_execute`, `list_error_check`.
  В конце — сводный отчёт с процентами и общим списком (отсортирован по IP).
- **Команда и пароль:** `execute_one_command()` шлёт `password` через
  `stdin.write(password + '\n')` для `sudo`. Это требует, чтобы на сервере
  пользователь мог выполнять sudo с паролем через TTY (параметр `get_pty`
  сейчас выключен).
- **Подстановка в командах:** поддерживается только плейсхолдер
  `{hostname}` (заменяется на `param['hostname']`). Закомментированный
  `{ip}` не активен.
- **stderr-эвристика:** некоторые нормальные сообщения (symlink от
  systemctl, sudo password prompt, rpm/dnf warnings) не считаются ошибкой
  и пропускаются — см. цепочку условий в `execute_one_command()`.
- **`ssh_robot_file_worker.py`** жёстко использует `import SL` и
  `import FOL` (модульно, а не через SETTINGS.fl, как декларируется в
  README — есть расхождение). Порт берётся всегда из
  `SETTINGS.default_SSH_port`, даже если задан `param['port']` (баг:
  переменная назначается, но не используется).

## Конвенции разработки

- **Стиль кода:** Python, PEP 8, модули плоские (без пакетов).
  Имена переменных: `snake_case` для функций/переменных, верхний регистр
  для файлов-конфигов (`SETTINGS`, `SL`, `FOL`, `MOD`).
- **Комментарии:** существующий код содержит технические комментарии
  (алгоритм, операторы сравнения) — сохраняй этот стиль при правках.
- **Приватность:** пароли/доступы живут только в gitignored файлах
  (`SETTINGS.py`, `SL.py`, `FOL.py`, `exclude.txt`). Не выноси их в
  отслеживаемые файлы. При создании новых модулей команд, содержащих
  реальные адреса/прокси, выноси значения в `SETTINGS.py` или
  параметризуй — не хардкодь секреты в коммитимых файлах.
- **Коммиты:** стиль — `type(scope): сообщение` (см. историю git:
  `fix(exclude):`, `chore(deps):`, `add:`). Сообщения на английском.
- **Тестов нет.** Проверка изменений — ручной запуск на тестовом стенде
  (используй модули вроде `c_pwd` / debug из `CentOS8.py`).
- **Зависимости:** обновляй `requirements.txt` через
  `pip freeze > requirements.txt` после изменений в окружении.
